# 成龙校区封闭试点实施规格（尚未启用）

状态：2026-10-29，仅为下一阶段的开发与验收规格。现有 `server/index.mjs` 是本机演示服务，拒绝生产模式启动；不要把它直接放到公网，也不要将真实资料写入演示数据库。

## 1. 身份、入驻与权限

小程序学生与代取员使用同一个客户端。学生通过 `wx.login()` 获取一次性 `code`，服务端调用 `code2Session`，只在服务端保存微信身份绑定并签发自己的短期会话。客户端传来的 `role`、`campus` 或 `approved` 不得决定权限。手机号仅在确实需要联系或找回时征得授权后绑定；如果启用短信，验证码由服务端发往经过审核的短信服务，不在响应中返回明文。小程序以微信身份恢复登录，默认不要求学生设置密码。

代取员先以学生身份提交申请；受保护的成龙主管账号核验资料、站点规则与培训结果，再批准角色、服务校区和接单上限，批准后默认离线。暂停资格应立即撤销新接单权限及现有会话；已接订单进入管理员人工处理。管理员继续使用独立网页后台与强认证，不使用小程序学生身份切换入口。试点部署必须扫描并拒绝全部 `/api/demo/*`，确认没有预置测试主管与总管理员账号。

**验收**：伪造角色、跨校区、未审核、过期或撤销会话均被服务端拒绝；短信码不会出现在接口响应、日志和页面中。保留脱敏权限测试与审核操作记录，真实证明材料只放受控存储。

## 2. 站点、订单与交接

首批只配置成龙校区 **一个** 获许可的站点、**一个** 现场核实的宿舍苑区和明确的公共交接点；服务端默认 `acceptingRealOrders=false`，仅授权记录、值班人员、隐私告知和验收齐全后才允许负责人开启。狮子山保持关闭。时段为 09:00–19:00 一小时一档，容量按审核过的代取员排班与站点营业时间配置，不直接沿用演示默认 3 单。

学生先看服务端报价、提交订单，再完成支付；只有服务端确认支付成功，订单才进入本校区任务池。代取员接单前只见站点、苑区、件数、时段和报价摘要；接单后只获得本单必要的取件凭证。取件码在正式数据库单独加密并按保留期限删除。楼下交接由学生当面提供一次性凭证，代取员提交后标记已交接，学生确认完成；联系不上学生、破损、遗失、超时进入人工待办，不能自动结算。

**验收**：20 名代取员并发抢同一单只成功一次；重试不新增订单；未付款不可接单；未核实站点不可下单；交接码过期、重复、猜错和他人越权均被拒绝；异常有负责人、处理时间与审计。

## 3. 支付、退款与代取员结算

确定采用“下单时付款”。正式后端保存独立的支付意图、支付结果、退款、应结算与对账记录，金额以整数分表示。状态至少区分 `awaiting_payment`、`paid`、`refund_pending`、`refunded` 和异常待人工核对；接单资格只由**服务端验证的支付结果**开启，客户端支付成功界面不能直接改订单状态。支付通知和退款通知须验签、幂等处理并与查单结果对照；定期将本地交易与微信账单核对，差异进入人工待办。取消、破损或无法交接按已公示规则退款，退款失败继续追踪，不因本地请求成功就显示退款到账。

学生确认且无未决异常后，生成代取员**待复核应结算**记录。首个收费阶段每周由指定负责人核对订单、实际收款、退款、手续费和约定报酬后执行付款，并登记付款凭证与复核人；**交接按钮不直接触发转账或分账**。代取员报酬标准、税务及是否允许微信分账必须在签约与商户资格核验后确定。未支付的演示订单不得生成真实应付款。

微信支付官方接入说明要求小程序认证、支付权限、商户号与 AppID 绑定，并提醒交易类小程序核对平台运营规范；实际发布时重新核验：[小程序支付接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015459512)、[支付回调](https://pay.wechatpay.cn/doc/v3/merchant/4012791902)、[退款回调](https://pay.wechatpay.cn/doc/v3/merchant/4012791906)、[分账常见问题](https://pay.wechatpay.cn/doc/v3/merchant/4014547102)。

**验收**：重复回调不重复入账；未知签名拒绝；付款未成功不接单；取消及异常退款可追踪；日账单金额一致；应结算不超过已核实收款扣除退款及约定费用；每周付款有双人复核和凭证。真正收款须另行批准。

## 4. 环境与发布门槛

建立独立 HTTPS 测试域名、合法小程序请求域名和多实例可用的正式数据库；配置迁移、备份、定期恢复演练、监控、告警与停服开关。小程序包、GitHub 和日志不得含 AppSecret、商户密钥、真实取件码或学生资料。通知采用用户授权后的平台消息，保留页内进度刷新和人工联系备用流程；不要承诺后台实时送达。

按“虚构数据开发者工具 → 真机与弱网 → 授权人员封闭试点 → 独立支付联调 → 收费试点 → 审核公开发布”逐门槛留记录。没有小程序账号、站点授权、合格人员、受控服务和安全验收，任何门槛都不能自动跳过。
