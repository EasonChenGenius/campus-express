# 待处理异常：处理流程与当前演示边界

更新时间：2026-10-23，适用于 V0.5.3 的**本机虚构订单**。系统没有真实配送、客服通知、退款或赔付能力；下文的现场核实和时限是正式试用前要落实的运营规则。

## 用户看到的流程

1. **发现问题并上报**：已接单的代取员可在订单详情选择“取件失败、包裹破损、学生暂无法交接、其他异常”。学生只能在“已交接、待确认”时上报。主管/管理员也可上报本校区订单。演示不接收自由文本、照片、真实手机号或取件码。
2. **订单暂停**：服务端把订单改为“待处理异常”，原配送进度停止，不能继续点“已取件/配送中/已交接/确认收货”。学生和代取员看到异常类型及“等待本校区管理员核实”。主管后台按上报时间从早到晚列出待办和等待分钟数。
3. **主管核实**：先确认包裹是否已经离开站点、目前由谁保管、有无破损/遗失、学生是否已经收到。此步需要真实运营时的线下证据与联系方式；演示版只有状态和固定原因，不能替代实际核实。
4. **选择处理结果**：
   - **核实后恢复原进度**：问题消除，原代取员仍有资格，回到上报前状态。
   - **确认未取件，重新开放接单**：仅适用于原状态“已接单”、包裹尚未取出且不是破损异常；清除原代取员，回到本校区任务池。重新接单前仍不展示取件码。
   - **人工关闭**：无法继续履约时停止订单，显示“异常已关闭”，与学生主动“已取消”区分。已经取件的关闭单仍占原预约时段工作量。真实业务必须先核实包裹去向、是否交还以及售后责任；当前没有自动退款。
5. **结果可追溯**：订单详情保留最近一次异常原因、处理结果和处理时间；服务端审计记录上报与处理人。若恢复后再次发生异常，新异常单独记录，不覆盖历史数据库记录。

## 上线前补齐的运营环节

- **值班与时限**：每校区指定值班主管和替补。建议上报后 10 分钟内首次查看、30 分钟内联系相关人；超过时限升级给总管理员。当前只有页面待办，没有自动通知、计时升级或值班排班。
- **证据与隐私**：正式环境可在受控系统记录站点核验、交接记录和处理备注；只采集必要信息，设权限、保留期和删除机制。不要把真实取件码、电话、聊天截图放到 GitHub、日志或普通 Issue。
- **学生告知**：通知学生“已暂停、预计处理时间、处理结果”，给出客服联系入口；关闭前说明包裹去向和后续安排。当前演示只能手动刷新看状态。
- **财务售后**：如将来收取真实费用，关闭异常订单后由经验证的支付状态决定退款/补偿流程，并记录对账结果。当前全部是未付款演示单，不存在退款。
- **特殊事故**：疑似遗失、破损争议、人身安全或禁运品直接停止配送，由有权限人员按学校/站点规则线下处理；不能仅靠“恢复”按钮解决。

## 测试要点

- 跨校区人员与无关学生不能读写异常；同一异常不能重复上报或重复处理。
- 代取员暂停资格后，主管不能将异常恢复给该代取员；破损单不能直接重新开放接单。
- 关闭状态与主动取消不同；处理结果对订单相关人可见，取件码仍仅对有权限人员可见。
- 双人同时处理同一异常时只有一个结果生效；正式数据库迁移后需重新做并发与恢复测试。
