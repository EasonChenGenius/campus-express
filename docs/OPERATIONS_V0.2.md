# 校园快取通｜双校区落地实施手册 V2.0

编制日期：2026-10-19  
适用场景：四川师范大学成龙校区、狮子山校区校园快递代取。  
**状态声明：这是试运营方案和开发验收标准，并非学校合作/快递站授权证明、营业许可或微信支付开通凭证。**

## 1. 项目目标

创建一个校内预约代取平台：学生可以选择校区、授权取件点、住宿区域、预约时段，提交订单并付款；平台将订单分配给具备本校区权限的代取员；完成交接后确认履约，后台集中管理两校区订单、运力与财务。

**一期限定：**普通生活快递，小件优先；仅在宿舍楼下指定地点交接；不承接贵重/违禁/易腐/需要本人身份核验或现场签署的包裹，遇站点代取规则限制按站点规定处理。

## 3. 用户角色与权限

| 角色 | 应有权限 | 明确禁止 |
|---|---|---|
| 学生 | 本人订单创建、查看、取消、确认收货、售后 | 看见其他学生订单/取件码，修改已支付金额 |
| 代取员 | 审核通过后，仅看本校区的待接单任务必要信息；接单后看该订单取件信息 | 跨校区接单、查看所有用户电话号码、修改价格或支付状态 |
| 校区主管 | 查看、审核、指派其负责校区订单和代取员 | 对另一校区擅自派单、导出与工作无关的个人信息 |
| 总管理员 | 双校区全局管控、对账、审批与日志审计 | 在个人聊天中传播取件码或导出无关敏感数据 |

**技术限制：**当前 Base44 在线项目尚不具备经验证的完整“代取员安全视图”。订单数据已设置为创建人或管理员可读、管理员可修改；不可直接把该模型开放给所有代取员使用。正式接单须由后端提供最小字段的“任务摘要”，审核代取员权限、校区归属并在抢单时进行事务性状态更新，接单成功后才通过受保护接口查询取件信息。

## 4. 订单字段与流程

订单唯一编号、用户ID、校区ID、已授权站点ID、苑区/楼栋/交接点、包裹规格/数量、预约时段、报价快照、支付状态、订单履约状态、代取员ID、创建/接单/交接时间戳、用户确认结果、异常与退款记录。

推荐状态机：

`草稿 -> 待支付 -> 已支付/待派单 -> 已指派 -> 已取件 -> 配送中 -> 待收货确认 -> 已完成`

可从规定状态进入 `已取消/退款中/已退款/售后中`。金额确认必须依微信支付服务器通知的签名验证及平台主动查询校验（金额、商户、订单号）。**不要因为前端点击支付按钮就把 paid 改成 true。**

### 派单规则

1. 过滤站点是否开放真实代取；校区、时段是否开放；
2. 仅展示给 **实名/学生资质核验通过 + 已绑定该校区 + 在线可接单** 的代取员；
3. 同一订单仅允许一名代取员抢单成功：由后端执行原子更新（必须同时满足`状态=待派单且courier_id为空`）；
4. 超时未接单可转为校区主管人工指派或退回用户并提示退款；
5. 取件、配送、交接每个动作写入审计日志；取件失败需要原因和退款流程；
6. 不向抢单前的代取员展示取件码、姓名、完整手机和宿舍具体房间。

## 5. 下单页一期设计

主流程：选择成龙/狮子山校区 → 选择已开放站点（未授权隐藏/禁用）→ 选择苑区楼栋及楼下交接点 → 填包裹信息、可选备注 → 选择配送时间 → 展示费用明细及服务协议/隐私说明 → 支付 → 等待接单与配送。

价格配置（全部仅为示例而非经营承诺）：
- 普通件基础服务费 3 元/首件；大件 5 元/首件（上限、重量须进一步设定）。
- 同站同订单每多 1 件加收 1 元；加急服务费 2 元；单笔上限和退款政策待确定。
- **金额由服务端计价**，不能相信浏览器/小程序上传的单价。

## 6. 校园代取员管理

1. 提交申请：校区、姓名、学号身份校验方式、联系方式、可服务时段；
2. 管理员核实身份、培训快递授权/隐私要求、签署服务协议后开通；
3. 代取员手动上线/下线，系统限制同时接单数量（建议试运营最多 3 单）并设置超时提醒；
4. 每完成一单记录订单、结算金额、投诉和质量评分；
5. 遇错件、异常件立即停止自行处理，转客服/站点联络；暂停严重违规账号；
6. 不要求代取员先交“保证金”参与试点，谨慎评估劳动关系、意外风险与责任保险。

## 7. 收款和结算设计

准备已认证的小程序、符合资质的经营主体及微信支付商户号；完成 AppID 与商户号授权绑定。微信支付商户官方文件：
- https://pay.wechatpay.cn/doc/v3/merchant/4015459512
- https://pay.wechatpay.cn/doc/v3/merchant/4012791895

支付回调和服务器对账后订单变为已支付；退款调用支付服务方正规退款接口；代取员的劳动报酬另设台账结算，不擅自以个人收款二维码绕过平台支付、账务与退款流程。涉及向个人发放报酬，应咨询适用财税义务。

## 8. 学校与站点沟通

先联系学校主管部门、后勤/生活服务部门及驿站，询问是否允许独立学生团队开展校内有偿代取、是否已有独家服务、是否需要校园经营许可或协议。确认之后再进行宣传和正式收款。没有学校官方合作时，不能使用校徽、学校官方认证标识或宣称“学校官方指定”。

可参考询问：
> 您好，我们在设计面向本校学生的自愿付费快递代取服务，计划从成龙和狮子山两个校区试运行。我们会严格遵守驿站的代取核验要求，并在宿舍楼下交接。想咨询学校及站点是否允许学生团队开展此类服务、需要办理哪些手续、能否明确可代取的站点和责任规则？如有合作要求，我们愿意先提交运营方案供审核。

## 9. 试运行指标与经营测算

示例：普通件收入 3 元，支付手续费暂按 0.6% 假设，代取员报酬 2 元，预计投诉补偿/营销/平台等变动预留 0.3 元，则单笔贡献毛利约 `3 - 0.018 - 2 - 0.3 = 0.682 元`；不含固定成本、税费、漏单、推广以及退款损失。以每单 0.682 元估算，要覆盖每月 1,000 元固定开支，约需 1,467 个有效订单/月。**全部参数都是预算假设，实际费率取决于商户行业类目，不能当已核准费率。**

先做每校区 2—3 名经培训代取员、1—2 个站点、各自 1 个宿舍苑区试运行。记录：有效下单转化率、可接单率、平均接单时间、准时交接率、错件率、投诉/退款率、毛利和回头客比例。若连续试运行中存在失件或明显隐私问题，先修复再扩大规模。

## 10. 正式上线验收（所有项通过才开支付/公开推广）

- [ ] 现场核实两个校区、每个开放站点、苑区楼栋和楼下交接点。
- [ ] 获得必要学校经营与快递站代取许可/授权；完成主体登记评估。
- [ ] 微信小程序注册、认证、类目资质、APPID/商户号绑定。
- [ ] 服务协议、隐私政策、个人信息删除与注销、投诉客服电话可用。
- [ ] 服务端权限审计：A学生绝不能看到B学生取件码；非本校区代取员不可查看/领取任务。
- [ ] 未授权站点关闭真实接单；学校地图候选点不被误标为已开放。
- [ ] 支付金额不可由前端篡改，支付回调具备验签、幂等、查单、失败重试与对账。
- [ ] 20人并发抢同一订单，最多只能成功1人。
- [ ] 代取员接单后取消、超时未取件、错件、退款与售后全路径测试。
- [ ] 敏感数据在服务器存储、传输受保护，日志不打印真实取件码，按期限删除。
- [ ] 对不同手机屏幕、弱网、断网、微信真机、支付沙箱/小额真实交易进行测试。
- [ ] 正式版发布审核通过，支付配置及客服已可用，再向学生公开二维码。

## 11. 运营人员不懂代码时的日常操作

学生侧只需二维码进入，登录、选择校区、选站点、选宿舍楼、预约。代取员只用自己的账号看本校区任务。管理员每天早、中、晚检查待派单列表、异常订单、站点状态和支付对账；所有管理操作保留时间和执行人记录。系统上线前先以纸面或内部记录进行小范围验证，不录入真实取件码到演示系统。
