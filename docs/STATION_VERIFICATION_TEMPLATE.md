# 双校区站点与交接点核验表（空白模板）

更新时间：2026-10-25。关联 [Issue #4](https://github.com/EasonChenGenius/campus-express/issues/4)。本表用于规划现场核验；**没有填写已授权站点**。真实联系人、电话、授权文件和签字资料应放在受控资料库，不提交 GitHub。

## 一站一张记录

| 项目 | 待填写内容 | 判定要求 |
|---|---|---|
| 校区与站点内部编号 | 待核实 | 编号不能与另一校区混用 |
| 站点名称、位置、营业时间 | 待核实 | 到现场复核；节假日和临时停业规则另记 |
| 学校/校区是否允许第三方有偿代取 | 待核实 | 明确适用范围、期限和负责人 |
| 站点是否允许代取及凭证使用 | 待核实 | 说明取件码、身份核验、代取失败和包裹异常规则 |
| 可覆盖的苑区与楼栋 | 待核实 | 东苑东1—东13 仅为待核实范围；西苑及狮子山楼号不能猜测 |
| 楼下公共交接点 | 待核实 | 现场确认安全、可识别、不妨碍通行；不要求宿舍房间号 |
| 值班主管与替补 | 待核实 | 覆盖营业时段，并明确异常升级方式 |
| 授权证据存放位置 | 仅填写受控资料编号 | 不写个人联系方式、不附授权原件 |
| 核验日期与复核日期 | 待核实 | 过期后重新核验 |
| 结论 | 未核实 / 不允许 / 有条件允许 / 已批准 | **未批准时保持真实下单关闭** |

## 核验完成后的技术验收

1. 服务端仅允许已批准、未过期、与用户校区一致且处于营业时段的站点成为可下单选项；未批准站点返回拒绝，不能靠页面隐藏代替服务端限制。
2. 校区主管只能管理本校区的站点和容量；变更要留操作者、时间、批准依据编号和前后状态的审计记录。
3. 当授权撤销或站点临时停业时，阻止新订单并明确处理现有未完成订单；保存一次虚构数据演练记录。
4. 验收证据为脱敏现场核验摘要、授权资料编号、接口拒绝测试、配置和审计截图。正式文件保留在受控位置。

当前 V0.6.1 的 `demo-cl`、`demo-sz` 均为**虚构测试点**，`verified=false`、`acceptingRealOrders=false`。这份模板不能让它们自动变成真实站点。
