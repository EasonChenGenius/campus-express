## 已发现问题与处置

1. **演示版完全依赖浏览器 localStorage。** 切换“学生/代取员/管理员”只是同页视图切换，不具备真实账号隔离。此设计已在页面与 README 明示，不能用于真实用户。
2. **模拟付款直接使订单进入待派单。** 这是演示逻辑，正式版必须由服务器验签、查单并核对金额后更改支付状态。
3. **Base44 的 Order 模型里含取件码与手机号，且 Courier 只有管理员角色读写。** 正式代取员接单与“接单前隐藏、接单后授权查看”需专门后端接口和安全测试。
4. **独立演示的同页“我的订单”会展示该浏览器中的所有本地订单。** 因无真实身份系统，不能让多人共用设备或输入真实资料。
5. **已修复演示版待接单列表的过度展示。** 代取员接单前只显示宿舍苑区与“接单后查看交接点”，不显示完整交接地址和备注；接单后仍可查看履约所需信息。这是界面隐藏，不构成正式权限控制。
6. **未发现可在不改变产品安全边界下直接修复的 Base44 代码问题**：源码访问被套餐限制，浏览器身份验证未完成。后续修复以取得源码和测试权限为前提。

## 下一次测试的通过标准

- 用虚构测试账号分别验证两校区下单、订单归属、校区隔离、代取员审核/接单、人工派单、取消、完成。
- 20 个并发接单请求同一订单只允许一个成功；重复提交不得重复扣款或派单。
- 未授权用户不能读取他人订单、取件码、完整手机号；管理员操作留下审计记录。
- 站点未核验时，生产下单必须由服务端拒绝；真实支付开关保持关闭。
