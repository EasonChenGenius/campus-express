# V0.3：从页面演示走向业务系统

更新时间：2026-10-21。当前版本是**仅限本机和虚构数据的后端原型**，没有真实身份认证、真实支付、正式站点或对外服务能力。

## 现在能做什么

| 模块 | V0.3 已实现 | 仍需完成 |
|---|---|---|
| 学生订单 | 本机 SQLite 保存测试订单；服务端核验校区、苑区、虚构测试点和报价；重复请求编号返回同一单；本人查看、待接单取消、交接后确认 | 微信登录、真实站点开放规则、真实订单、取消后的退款、异常单 |
| 双校区 | 成龙与狮子山独立任务池；主管仅能看本校区 | 校区主管正式账号、站点与楼栋现场核验、营业时间和容量配置 |
| 代取员 | 测试员审核状态；审核通过才看本校区任务；接单前只收必要摘要；接单后才取到测试码和楼下交接点 | 身份审核、上线下线、限单、超时、异常件、结算 |
| 派单 | 接单与人工派单都用数据库条件更新；重复抢单返回冲突 | 多进程/多机数据库方案、自动派单、超时改派、排班 |
| 后台 | 双校区订单、代取员审核、人工派单和动作审计 | 真正管理员登录、分级权限、客服售后、数据报表、备份恢复 |
| 支付 | **始终关闭**；只显示服务端计算的模拟报价和 `demo_not_paid` | 经营资质、商户接入、验签、查单、退款、对账 |

## 给非程序员的运行方式

1. 电脑安装 Node.js 24.12 或更新版本。
2. 在项目文件夹打开终端，运行 `npm start`。此项目没有第三方 npm 依赖，不需要 `npm install`。
3. 浏览器打开 `http://127.0.0.1:3000`。选择“学生甲（测试）”，选择宿舍苑区并填 `TEST-123456` 等虚构测试码创建订单；楼下当面交接位置由系统自动显示。
4. 切换“成龙代取员甲（测试）”接单、更新配送；切回学生确认。管理员可审核或派单。
5. 运行 `npm test` 检查后端。停止服务按 `Ctrl+C`。本地数据库保存在 `data/campus-express.sqlite`，已被 Git 忽略；不要往其中录入真实资料。

## 接下来的开发顺序

1. **身份与数据保护：**微信小程序登录由后端换取身份；正式用户、角色、校区、代取员审核资料由可信流程绑定。删除“点击选身份”的测试登录。制定数据加密、保留期限、访问记录和注销流程。
2. **站点与履约：**逐站取得代取许可、实地确认位置与时段。服务端只允许已核验且获授权站点接受正式订单；加入禁运品、异常件、超时、改派和申诉处理。
3. **订单与派单：**将状态机、幂等请求、并发抢单迁往正式数据库；做 20 个不同代取员、多进程并发和断网重试测试；加入排班、限单、通知。
4. **运营后台：**正式管理员与校区主管登录、审批留痕、客服工单、退款审核、结算记录、报表、备份和恢复演练。
5. **小程序与支付：**学生和代取员小程序接现有 API 契约；等主体、站点授权、隐私材料和支付商户条件齐备后另行开发验签、查单、退款、对账；得到负责人确认后才考虑真实支付或正式运营。

## 当前架构与限制

`web/` 是三角色测试控制台；`server/index.mjs` 是本机 HTTP API；SQLite 是本地测试数据库；`test/` 是自动化验证。服务仅监听 `127.0.0.1`。测试身份不需要密码，任何能访问本机服务的人都能切换身份，因此**不能放到公网或给真实学生使用**。当前测试只证明单 Node 进程内的 SQLite 条件更新；正式部署还需独立的身份系统、正式数据库、监控、备份和安全测试。

取件码形态和“楼下当面交接位置”的具体解释见 [V0.3.1 格式说明](PICKUP_CODE_AND_HANDOFF.md)。
