# V0.5 本机演示接口补充

更新时间：2026-10-23。建立在 [V0.4 订单接口](V0.4_API_CONTRACT.md)之上。`GET /api/capabilities` 返回 `version: 0.5.3`、`apiContract: 6`、`mode: LOCAL_DEMO_ONLY`；真实身份、真实订单与支付标记仍为 `false`。小程序只连接本机 `127.0.0.1`。

`POST /api/demo/login` 仍只允许选择虚构账号，返回令牌、用户和 `expiresAt`。令牌 30 分钟后绝对失效；`POST /api/session/logout` 需携带 Bearer 令牌并立即撤销。过期或撤销后受保护接口返回 401。演示会话只存在当前进程内，重启服务会全部失效；这不是正式微信认证或持久会话方案。

| 接口 | 权限与行为 |
|---|---|
| `GET/POST /api/couriers/me/availability` | 代取员读取或设置 `{online:boolean}`；未审核者不能上线。返回 `online,approved,maxActive,activeCount`。离线后已有任务仍可继续处理，但不能新接单。 |
| `POST /api/couriers/{id}/capacity` | 本校区主管或总管理员设置 `{maxActive:1..5}`。接单与人工派单由服务端检查审核、上线状态和当前处理中订单数。 |
| `POST /api/orders/{id}/exception` | 本单代取员、已交接待确认的学生，或有管辖权的管理员上报 `{reason}`。固定理由：`pickup_failed`、`damaged`、`student_unavailable`、`other`。订单进入 `exception`，不接收自由文本或真实个人资料。 |
| `POST /api/orders/{id}/resolve` | 本校区主管或总管理员提交 `{resolution}`：`resume` 恢复原进度、`retry` 重新开放接单、`close` 关闭订单。`retry` 仅在尚未取件且非破损的 `assigned` 阶段允许；原代取员资格暂停时不能 `resume`。`close` 后订单状态为 `closed`，区别于学生主动 `cancelled`。 |
| `GET /api/operations/queue` | 主管只见本校区、总管理员见双校区；返回 `exceptions` 和创建超过 30 分钟仍待接单的 `overdue`。目前只是页面待办，没有自动通知或自动派单。 |
| `GET/POST /api/slots/capacity` | 主管只可查看或设置本校区，总管理员可选双校区。`GET` 使用 `?campus=chenglong` 等，返回每档 `capacity,booked,remaining`；`POST` 使用 `{campus,slot,capacity}`，容量为 0–20 且不得低于已预约数。 |

`GET /api/catalog` 对学生只返回本校区未过期且有剩余名额的时段，每项含 `value,label,capacity,booked,remaining`。默认每校区每小时 3 单；服务端在事务中再次检查容量，避免并发下单超额。已满时返回 409，客户端刷新时段；同一请求编号原样重试仍返回原订单。待接单订单取消后释放名额；已经取件的异常订单即使由管理员关闭，仍计入原时段工作量。

`GET /api/orders` 与 `GET /api/orders/{id}` 仍执行原有归属与校区隔离。接单前任务摘要不含虚构取件码、学生编号和交接位置。当前待处理异常用 `exception` 展示；最近一次已处理异常用 `lastResolution` 展示原因、结果、时间，不展示处理人身份给学生。异常处理操作记录到审计日志。后台异常队列按上报时间从早到晚排列。完整流程见[异常处理流程](EXCEPTION_WORKFLOW.md)。已有 V0.4 本机数据库启动时自动增加代取员上线、接单额度与异常记录表；迁移仅针对本机虚构数据，不是正式数据库迁移方案。

## 需要人工验收的场景

1. 两校区分别创建虚构订单；离线代取员接单失败，上线后可接。达到接单上限时新接单和后台派单都应失败。
2. 已接单但未取件的订单上报“取件失败”，主管从后台待办选择“重新开放接单”；再次查看任务池时，接单前无取件码。
3. 已取件的订单上报“包裹破损”，主管不能直接重新开放接单，只能先核实包裹去向后恢复原进度或关闭。
4. 超过 30 分钟无人接单的测试订单出现在本校区主管待办；跨校区主管和普通代取员无权访问他校区待办。
5. 主管将某时段设为 2 单后并发提交 10 个测试订单，仅 2 单成功；另一个校区仍可使用同一时段。取消一单后剩余名额恢复 1；低于已预约数的设置被拒绝。

测试账号可随意切换；这些场景只验证演示逻辑，不构成真实身份、站点或支付验收。
