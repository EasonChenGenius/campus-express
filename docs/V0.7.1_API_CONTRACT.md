# V0.7.1 本机演示接口补充

`GET /api/capabilities` 返回 `version: 0.7.1`、`apiContract: 10`。其余功能和安全边界沿用 [V0.7 契约](V0.7_API_CONTRACT.md)。

## 创建订单的逐件取件码

`POST /api/orders` 的 `qty` 仅为 1—3，`pickupCodes` 必须是长度与 `qty` 相同的数组。每项必须为 `TEST-` 开头的虚构测试码。例：`{ "qty": 2, "pickupCodes": ["TEST-123456", "TEST-5-2-0042"] }`。允许两个包裹使用相同的测试码，因为同一提货凭证可能对应多个包裹；服务端仍按件数逐项校验。单件旧客户端的 `pickupCode` 字段暂兼容，多件订单不能只提供一个码。

学生本人和成功接单的代取员可在订单详情看到按件排列的 `pickup_codes`；接单前任务摘要及管理员视图不返回该数组。`pickup_code` 暂保留首件兼容字段，也只对上述授权身份返回。相同请求编号重试时比较完整码列表；不同列表返回 409，避免把一份订单错当作另一份。

旧本机数据库启动时自动添加 `pickup_codes` 列。旧订单没有逐件历史数据，仅显示原先保存的一个码，不推断其他包裹的码。本版本仍只允许虚构数据，未实现正式环境的取件码加密与保留期。
