# V0.7 本机演示接口补充

`GET /api/capabilities` 返回 `version: 0.7.0`、`apiContract: 9`、`mode: LOCAL_DEMO_ONLY`。`realAuthentication`、`realSms`、`realOrders`、`realPayment` 和 `closedPilotReady` 仍为 `false`。旧接口见 [V0.6.1 契约](V0.6.1_API_CONTRACT.md)。

## 虚构代取员申请

| 路由 | 角色 | 行为 |
|---|---|---|
| `GET /api/courier-applications/me` | 学生 | 返回自己的申请状态；未申请为 `{ "status": "none" }`。 |
| `POST /api/courier-applications`，正文 `{}` | 学生 | 服务器从当前登录身份确定校区，建立 `pending` 申请；重复待审或已通过返回 409。请求中的角色、校区或审核字段不起作用。 |
| `GET /api/courier-applications` | 主管、总管理员 | 主管仅见本校区申请；总管理员见双校区。 |
| `POST /api/courier-applications/:studentId/review`，正文 `{ "approved": true/false }` | 主管、总管理员 | 仅审核待审申请；跨校区主管返回 404。通过时创建已审核、默认下线的虚构代取员账号，并写审计；并发审核只能成功一次。 |
| `GET /api/demo/accounts` | 本机演示入口 | 在预置测试账号后列出已通过申请产生的代取员测试账号；**任何可访问本机演示的人都能切换测试身份**。 |

拒绝后学生可重新提交虚构申请。接口不接收真实姓名、证件、真实手机号或证明文件。正式版本必须用可信微信身份绑定和受保护的审核资料存储替换此流程，关闭全部 `/api/demo/*` 入口。

## 页面更新与错误处理

- 服务端接单、状态更新、异常上报和审核操作同步写入数据库并返回最新结果。
- 小程序代取任务、学生订单列表和订单详情在页面可见时约每 15 秒重新读取；离开页面后停止。网络请求失败显示错误，用户可手动刷新。**这不是后台实时推送**。
- 学生提交时段已满返回 409 后，小程序重新读取可预约时段并保留当前虚构取件码、站点、苑区与包裹选项；下单仍使用请求编号防止同一请求重复创建。
- 网页后台可按订单状态筛选，后台待办可直接定位到对应订单；筛选仅影响显示，不改变服务端权限。
