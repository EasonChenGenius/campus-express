# 微信身份与上线实施顺序

更新时间：2026-10-26。当前 V0.7.0 **只供本机虚构数据演示**。网页的 `TEST-` 号码、页面验证码和密码找回只用于体验流程；代取员申请与后台审核也仅是虚构数据演示，没有短信发送或可信身份。30 分钟会话和退出功能仅减少演示时旧令牌残留；任何能访问演示服务的人仍能选择任意测试身份，不能用于真实学生或代取员。

## 下一阶段按此顺序开发

1. **小程序主体与 AppID**：用户持有并管理小程序账号；开发者工具导入 `miniprogram/`，核对类目、主体与隐私要求。AppSecret 只交给受控服务端环境，不放在小程序包、浏览器、仓库或 Issue。
2. **可信登录**：小程序调用 `wx.login()` 获取一次性 `code`，发送给后端。后端通过微信 `code2Session` 换取 OpenID，验证响应后在服务端查找或创建绑定记录，签发短期自有会话。客户端提交的角色、校区、审核状态一律不作为授权依据。未绑定用户只能进入受限的注册/审核流程。
3. **角色与审核**：学生选校区后由管理员或可信资料核验绑定；代取员须经管理员审核并指定服务校区；管理员采用独立的强身份验证。身份、角色与校区保存在正式数据库，修改均记录审计。退出和管理员撤销须立即使所有对应会话失效。
4. **正式数据层**：把订单、用户绑定、会话、审计从单机 SQLite 迁至有备份/恢复演练的受控数据库。敏感取件码加密并设置删除期限；跨实例事务、并发抢单、幂等重试和容量扣减重新验收。
5. **独立 HTTPS 测试环境**：配置受控域名和小程序合法 request 域名，关闭 `/api/demo/*`、测试身份和 `TEST-` 测试订单入口。正式服务默认拒绝真实下单，直至授权站点、人员与隐私告知均核验通过。
6. **封闭试用再发布**：先用虚构数据在微信开发者工具和真机完成登录、权限、断网、取消、异常及双校区测试；获得学校/站点授权后，再由项目负责人确认限定人员与站点的真实试用。真实支付另行设计并单独确认。

## 代码分界

- 当前：`POST /api/demo/login` 选择虚构账号，网页学生还可使用 `/api/demo/register`、`/api/demo/password-login` 和 `/api/demo/reset-password` 体验流程；虚构代取员申请通过后也只生成可选的测试身份；`POST /api/session/logout` 撤销当前令牌；30 分钟绝对过期。所有数据只应在本机测试。
- 下一开发版本：单独新增真实微信登录适配层及身份绑定表；正式环境禁用演示登录。没有 AppID、服务端密钥和可控 HTTPS 环境时，不能宣称已完成微信登录。
- 管理后台：正式管理员认证与双因素/强身份策略应独立于学生小程序登录；当前网页后台的“管理员测试身份”没有真实保护。

参考官方入口：[微信小程序登录](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)、[code2Session](https://developers.weixin.qq.com/miniprogram/dev/server/API/user-login/api_code2session.html)、[小程序网络](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。实际接口与发布条件应在接入时重新核对微信开发者平台，因为本次无法直接打开其官方文档页面。
